10 / CONTROL THROUGHOUTAROUND EVERY LAYER

outruns permission.

The more useful the firm’s memory becomes, the more its boundaries matter. This architecture is designed around control of what is known, who can use it and what may be done.

Knowing ≠ permission to act
Authorised sources & matter boundaries +

The design starts with user identity and source access. Matter boundaries must constrain retrieval and reuse, even where context is connected.

Evidence & controlled execution +

Keep source evidence distinct from interpretation. Authorise actions separately, with approval and exception paths defined for each operation.

Models & auditability +

Existing policies prohibit using Customer Data for model training. The memory design needs a reviewed audit model that records actions without unnecessarily exposing sensitive content.

Retention & deletion +

Persistent memory needs explicit retention rules, deletion propagation and treatment of derived context. These require review against the current transient-processing policy before production.
